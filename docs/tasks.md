# Tasks

Work top to bottom, one task per session. Tick a task (`- [x]`) only when its "Done when" check passes.

- [x] **1. Scaffold the app.** Next.js + TypeScript + Tailwind + Vitest; `lib/types.ts` from the spec;
  Supabase `cases` table matching `Case`; env loading from `.env.local`.
  - Done when: `npm run dev` shows the home page, and a test case saves and reads back.
  - Note: Supabase new keys → env vars `SUPABASE_URL` + `SUPABASE_SECRET_KEY` (server only, no anon key).
    Schema in `supabase/migrations/0001_cases.sql`; round-trip check is `npm run test:db`.

- [x] **2. Create sample data.** In `/samples/{a,b,c}`, a synthetic bill and EOB (PNG or PDF) plus
  `expected.json`, matching the sample table in the spec. Use invented names and addresses.
  - Done when: all six documents and three `expected.json` files exist and validate against the types.
  - Note: generated by `npm run samples` (headless Chrome → PNG). Also added `samples/profile.json` (synthetic
    redaction profile) and `lib/schemas.ts` (zod, compile-time locked to `lib/types.ts`). Check: `samples/samples.test.ts`.

- [x] **3. Build the upload screen.** Two drop zones labelled Bill and EOB, with previews.
  - Done when: both previews show for each sample pair.
  - Note: images only (PNG/JPEG/WebP); PDFs aren't accepted since Tesseract can't read them directly.
    Check: `npm run e2e:upload` (drives local Chrome via playwright-core; needs `npm run dev` running).

- [x] **4. Add on-device OCR.** Tesseract.js in a web worker; show raw text in a debug panel.
  - Done when: text appears for all samples, and no network request carries document text.
  - Note: Tesseract worker, WASM core and English data are self-hosted from `public/tesseract` (copied on
    `postinstall`, git-ignored), so OCR makes zero external requests. Check: `npm run e2e:ocr`.

- [x] **5. Add redaction.** Profile form saved in `localStorage`; apply the redaction rules from the spec;
  show a highlighted redacted view.
  - Done when: no profile value appears in the redacted text of any sample (unit test + visual check).
  - Note: beyond the spec, profile values match across case/spacing/punctuation, DOB in any common format, and
    single name words are also redacted ("RIVERA, JORDAN"). Unit tests run on real OCR fixtures
    (`samples/*/*.ocr.txt`, from `npm run samples:ocr`); browser check: `npm run e2e:redact`.

- [x] **6. Extract with AI.** `/api/extract` sends redacted text to Claude and validates the JSON.
  - Done when: extracted totals match `expected.json` for all three cases.
  - Note: provider is Gemini by default (`gemini-3.5-flash`, free tier) because the Anthropic account has no
    credits; Claude stays available via `EXTRACT_PROVIDER=claude`. Route also refuses text that still matches
    redaction patterns. Check: `npm run test:ai` (all lines and totals, not just totals). ~15s per call.

- [x] **7. Write the flag rules, tests first.** Pure `checkFlags(bill, eob)` behind `/api/check`.
  - Done when: tests pass — A gives 0 flags, B gives 1 `duplicate`, C gives `over_patient_responsibility`
    with a $367 difference.
  - Note: also added `POST/GET /api/cases` (needed by `/api/check`). Edge-case decisions recorded in the spec.
    `/api/check` refuses (409) once a case is sent.

- [x] **8. Build the review screen.** Bill and EOB lines side by side, flagged rows highlighted, a
  plain-language explanation per flag, and a "to question" total.
  - Done when: case C shows "$367 to question".
  - Note: review lives at `/cases/[id]`; home page now runs the whole flow (read → redact → "Check my bill").
    Sending is disabled until a profile is saved. Check: `npm run e2e:review` (also verifies no profile
    value is in any `/api/extract` body, and no sideways scroll at 390px).

- [x] **9. Draft and edit the letter.** `/api/letter` drafts from the flags with placeholders; editable text
  area; placeholders filled in the browser on approval.
  - Done when: the letter cites dates, descriptions and amounts, and the `/api/letter` request holds no
    profile values.
  - Note: letter is a fixed template (no AI), agreed with the user. Edits stay in the browser. Check:
    `npm run e2e:letter` (request body is exactly `{ caseId }`).

- [ ] **10. Send.** "Approve and send" calls `/api/send`, which creates a Lob certified letter (test key).
  - Done when: Lob returns a letter id and preview link, and the case status becomes `sent`.

- [ ] **11. Track.** Handle Lob tracking events in `/api/lob-webhook`; set a reminder 30 days after sending;
  add a "Simulate delivery" button (test mode may not send tracking events).
  - Done when: a status change to `delivered` shows on the dashboard.

- [ ] **12. Build the dashboard.** All cases with status chips and a total "money saved".
  - Done when: after running case C, it shows `sent` and $367.

- [ ] **13. Polish the demo.** Seed and reset buttons, loading states, readable error messages.
  - Done when: the full demo runs three times in a row without a restart.
